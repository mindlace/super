Worktree→main path fallback, with main as read-only

spec_reader · worktree worktree-main-fallback-readonly · 2026-06-23

Problem

When a worktree is merged to main and its directory is removed, any tab still pointing at the old worktree path becomes a dead link. Clicking the tab hits /api/spec with a path that no longer exists, the read fails, and the tab can't be switched to.

Note assertSpecPath() is not the blocker. It validates the worktree path fine; the file is simply gone from disk.

Decisions

Adopt the main path
The server reports the path it actually read; the client updates its selection, the opened tab and localStorage to that path.
Main is read-only
If the file lives in a project's main checkout, the editor is read-only and writes are refused.
The tab says where it lives
The caption gains a main label, and that label is the read-only signal.
