HTML spec writers

supercomposer, and superpowers through a new overlay plugin, write specs and plans in the semantic HTML format.

Intent

The semantic HTML format (docs/spec-format.md) and the superspec reader that renders it have landed, but nothing writes the format yet. Every design doc, spec and plan the plugins produce is still markdown. This change makes the writers produce the format, so documents get stable #id anchors, diagrams, callouts and step checklists that superspec renders as intended.

Goals, non-goals, anti-goals

Goals

  • supersonic:supercomposer writes its design doc and every spec as an HTML fragment that follows the format.
  • A new plugin, superpowers-html, makes superpowers:brainstorming write specs and superpowers:writing-plans write plans in the format.
  • HTML plans still execute: superpowers:subagent-driven-development and superpowers:executing-plans get the brief for one task out of an .html plan.
  • The jev checks that read design docs and specs keep working on HTML.

Non-goals

  • Converting existing markdown specs and plans. Old documents stay as they are and keep working.
  • Changing superspec or the format itself.
  • The superconductor ledger, operator reports and other working files under .superpowers/. They are not specs and stay markdown.

Anti-goals

  • Editing or forking superpowers' own files. The new plugin overlays superpowers the way superpowers-jev does; it never patches the installed copy.
  • Making supersonic depend on superpowers-html. Each plugin works without the other.
  • Breaking markdown plans. A .md plan runs exactly as it does today.
  • A check that turns itself off silently on HTML. If a jev builder can't read a file it says so.

Constraints

  • Plugins ship standalone, but a symlink inside a plugin is copied into the installed plugin when the marketplace is cloned. So each plugin that writes the format holds a symlink to docs/spec-format.md, the one and only copy. No duplicates are maintained.
  • The superpowers version these notes were written against is 7.0.2. The overlay names the upstream steps it changes by section heading and checks the installed version, as superpowers-jev does with jev compat.
  • Hooks fail open: an error in the overlay never blocks a session.
  • Python stays stdlib-only (html.parser), matching superpowers-jev.
  • Each changed plugin bumps its version in plugin.json; installed copies update only on a version change.

Approaches

The open question was plans. superpowers' plan executors find tasks with an awk script that matches markdown ### Task N headings, so an HTML plan stops them with "no task headings found".

A. Plans become HTML too, with an HTML-aware task extractor (picked)
superpowers-html ships its own task-brief and tells the executors to use it for .html plans. Plans get the format's step ids and checkboxes, which the format was designed around. Cost: the overlay depends on how the upstream scripts work today, guarded by the version check.
B. Specs only; plans stay markdown
Nothing can break, but plans miss the format, and superspec shows half of each pair in the old style.
Decision Approach A, chosen by Ethan.

Design

supersonic 0.3.0

  • supercomposer/SKILL.md: the design doc moves to docs/superpowers/design/YYYY-MM-DD-HHMM-<topic>.html and specs to docs/superpowers/specs/YYYY-MM-DD-<slug>-design.html. Both follow the format. The required sections keep their names and become sections with stable ids; the interface, traceability and coverage tables become captioned tables with ids (for example tbl-traceability). The skill points at the format reference, reached through a symlink in the plugin, instead of restating it.
  • superconductor/SKILL.md and operator-briefing.md: accept a design package in either format, so a run composed before this change still resumes. Operators are subagents, and the superpowers-html SessionStart note never reaches them. So when superconductor builds an operator's prompt, it checks whether superpowers-html:html-docs is among its available skills. If it is, it adds one line telling the operator to load that skill before superpowers:writing-plans. If it isn't, the prompt stays as it is today. The briefing file itself stays static.

superpowers-jev 0.7.0

  • builders/spec.py (jev coverage --design) reads the traceability table from an HTML design doc: the table whose caption or enclosing section heading contains "traceability".
  • builders/ledger.py (spec_summary) takes the title from the h1 and the goal from the section headed "Goal".
  • Both choose the parser by file extension and keep the markdown path. When an HTML file has no table or title where expected, they report it instead of returning nothing.
  • The spec text sent to Jev for an HTML spec is its extracted text, not raw HTML: tags stripped, SVG dropped apart from its title, block breaks kept. That keeps blobs under the size cap and comparable with past markdown runs, so the question templates don't change.

New plugin: superpowers-html 0.1.0

  • SessionStart hook, built like superpowers-jev's (polyglot launcher, a 10 s timeout, fails open). It injects one note: superpowers-html is active; before writing a spec or a plan, or executing an .html plan, load superpowers-html:html-docs.
  • html-docs skill, an overlay that never reorders a superpowers step. It says:
    • brainstorming: write the spec to …/specs/YYYY-MM-DD-<topic>-design.html in the format (brainstorming lets the user's preference override the path and format).
    • writing-plans: write the plan to …/plans/YYYY-MM-DD-<feature>.html. The required header becomes the header plus a section with the Goal, Architecture, Tech Stack and Spec lines; Global Constraints is a section with id sec-global-constraints. Each task is a section with id sec-task-N and an h2 starting "Task N:"; each step is a checklist li with id tN-sK. The handoff messages name the .html path.
    • subagent-driven-development: for an .html plan, run superpowers-html's task-brief where the upstream skill runs its own. executing-plans: run superpowers-html's task-start in place of upstream's.
    • Progress stays where upstream keeps it, in the workspace ledger. Nobody ticks plan checkboxes during execution, just as nobody ticks - [ ] in a markdown plan today, so plan edits never land in a task's review diff.
    • It reaches the format reference through a symlink to docs/spec-format.md and runs a version check against the installed superpowers; on a version it doesn't know, it warns once and carries on.
  • bin/task-brief, the same command line, output line and exit codes as upstream's ([-C DIR] PLAN_FILE TASK_NUMBER [OUTFILE]; 2 usage, 3 not found). For a non-.html plan it hands off to the installed upstream script unchanged. For an .html plan it finds the section whose first heading starts with "Task <id>", matching ids as whole strings as upstream does, and writes that section's HTML verbatim. The default output path comes from the upstream sdd-workspace, so both skills share one workspace. The upstream install is found the way jev compat finds it, through ~/.claude/plugins/installed_plugins.json. A deeper task section whose id extends the requested one (Task 7a inside Task 7) stays in the brief, as upstream.
  • bin/task-start, the same command line and brief:/base: output as upstream's executing-plans script, built on superpowers-html's task-brief.

Marketplace and tests

  • .claude-plugin/marketplace.json and the README list superpowers-html.
  • tests/test_manifests.sh expects three plugins. New tests cover: each plugin's format-reference symlink resolves to docs/spec-format.md; supercomposer names .html paths; task-brief on an HTML plan fixture (found, not found, Task 6 vs 6b, markdown pass-through); the hook emits its note and exits 0 on error; the jev builders on HTML fixtures.

Calls made without asking

  • Operator plans are HTML when superpowers-html is installed (see supersonic 0.3.0).
  • executing-plans gets its own task-start instead of instructions to stitch one together.
  • Checkboxes are never ticked during execution; the ledger stays the progress record.
  • Jev receives extracted text from HTML specs.
  • The version check accepts superpowers 7.x and warns on anything else, as jev compat does.
