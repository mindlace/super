Supersonic run records outside the repo: implementation plan

Moves every composer and conductor record to ${SUPERSONIC_HOME:-~/.supersonic}/superconductor/<repo-key>/<design-slug>/ through one shipped script, and commits only the design doc, the specs and the build graph.

For agentic workers REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
The only files supersonic commits to a project are the design doc, the specs and the build graph (plus operators' own plans); every other record goes to one per-design directory outside the repo that survives git clean -fdx and a deleted clone.
Architecture
A new script, plugins/supersonic/skills/superconductor/records.sh, prints and creates the records directory, migrates an old in-repo one, and reports whether user settings cover the records home. Both skills call it once and carry the printed path as <ledger dir>, which every downstream command already takes as a value. beat.sh stops deriving the project from the ledger dir's position and reads it from the ledger's Package worktree: line instead.
Tech Stack
POSIX sh and perl with JSON::PP (stock macOS, as beat.sh), git 2.31 or newer; skill text in Markdown; grep-style shell tests run by sh tests/run.sh.
Spec
docs/superpowers/specs/2026-11-26-supersonic-local-records-design.html

Global Constraints

  • Records directory: <home>/superconductor/<repo-key>/<design-slug>/. <home> is $SUPERSONIC_HOME when set, else ~/.supersonic.
  • <repo-key> is the output of git rev-parse --path-format=absolute --git-common-dir with its trailing /.git removed, with every non-alphanumeric character replaced by - (/Users/a/Projects/sfhousing becomes -Users-a-Projects-sfhousing). Every worktree of one repository, including nested package worktrees, maps to the same key.
  • Nothing goes under ~/.claude/ (nor ${CLAUDE_PLUGIN_DATA}): a protected path stalls operators in acceptEdits.
  • The directory's contents and layout are unchanged: ledger.md, assignments/, prompts/, questions/, rulings/, checkpoint-*.json, surveys/, timer.
  • The composer commits exactly the design doc, the specs and the build graph. Survey reports, fresh-eyes reports, amendments' notes, briefs, the composer's helper scripts and the ledger are never committed. The conductor never copies records into a branch and never commits them.
  • No local git repo in the records directory.
  • The handoff is unchanged: the package is committed on superconductor/<design-slug> and the conductor adopts that branch.
  • Out of scope: .superpowers/jev/, .superpowers/sdd/, cleaning records already committed in other projects, and this repo's own .gitignore line .superpowers/ (tests/test_manifests.sh:34 requires it; leave it).
  • The settings line the skills and README offer is exactly { "permissions": { "additionalDirectories": ["~/.supersonic"] } }, in ~/.claude/settings.json, or $CLAUDE_CONFIG_DIR/settings.json when that is set. The skills edit it only after the user says yes.
  • Skill text is a prompt: write it as current state, no "previously" or "changed from".
  • supersonic version 0.7.0 in plugins/supersonic/.claude-plugin/plugin.json. .claude-plugin/marketplace.json carries no version field; leave it.
  • Conventional Commits; no Claude or AI attribution anywhere. Never compound cd ... && cmd.

Review Focus

  • A repo whose path holds a space, a dot or a hyphen: the key encodes every one of them to - and the directory is created. Test: t1-s1 (encoding).
  • The composer in its own worktree, the conductor in the main checkout and a package worktree nested under .claude/worktrees/ of another worktree all print the same directory, so the conductor finds the composer's ledger. Test: t1-s1 (shared key).
  • A run started before 0.7.0 and resumed after: the old in-repo ledger is moved, tracked files stay, untracked copies go, paths inside the copied ledger and assignments point at the new directory, and a second resume does nothing. Tests: t1-s1 (migrate), t2-s1 (live operators are told).
  • User settings that are missing, lack permissions, hold invalid JSON, name ~/.supersonic or a parent of it, or live under $CLAUDE_CONFIG_DIR: the check answers yes only when the records home is covered. Test: t1-s1 (check).
  • beat.sh with a ledger dir outside the project: units without a worktree field still resolve to <main checkout>/.claude/worktrees/<design-slug>-<unit>. Test: t2-s1 (fixture moved out of the project).

Interfaces

  • Produces, for tasks 2 and 3 (run from any directory inside the repository's main checkout or any of its worktrees):
    • sh records.sh <design-slug>: creates the records directory (mkdir -p) and prints its absolute path as the only stdout line; exit 0. A slug that is empty or not ^[A-Za-z0-9][A-Za-z0-9._-]*$ exits 2 with a usage line on stderr and creates nothing. Outside a git repository: exit 1, records.sh: not in a git repository on stderr.
    • sh records.sh migrate <design-slug>: when <records dir>/ledger.md is absent and <main checkout>/.superpowers/superconductor/<design-slug>/ledger.md exists, copies that whole directory into the records directory, replaces every occurrence of the old directory's absolute path with the new one in the copies of ledger.md and assignments/*.md, deletes the copied originals that git -C <main checkout> ls-files does not list, removes directories left empty, and prints exactly one line migrated <n> files from <old dir>; <k> tracked left. Otherwise it prints nothing. Exit 0 either way.
    • sh records.sh check: prints three lines, home: <absolute records home>, settings: <settings file> ($CLAUDE_CONFIG_DIR/settings.json when set, else $HOME/.claude/settings.json) and covered: yes or covered: no; exit 0. Covered means some entry of permissions.additionalDirectories, with a leading ~ expanded to $HOME and trailing slashes removed, equals the home or is a parent of it. A missing file, missing key or invalid JSON is no. Needs no git repository.
