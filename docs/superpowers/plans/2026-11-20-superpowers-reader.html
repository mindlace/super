superpowers-reader implementation plan

Builds the plugin that shows a just-written spec or plan in the browser pane, served by a zero-dependency Node server and painted by superspec's stylesheet.

For agentic workers REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps are checklist items; progress is kept in the workspace ledger, not in the plan.

Overview

Goal
A new marketplace plugin, superpowers-reader, that opens a spec-format .html document under any docs/ directory in the desktop app's browser pane as soon as it is written, and prints a link to it in the CLI.
Architecture
A hooks module (hooks/register.ts) hears Write and Edit, starts reader/server.mjs once per session as a child process, and points its own browser-pane tab at http://localhost:<port>/s/<absolute path>. The server wraps the fragment in a small page under a strict Content-Security-Policy; reader/page.js highlights code, disables checkboxes and polls for changes. One pure module, reader/shape.mjs, holds the path and article rules both sides share.
Tech Stack
Node 20 or newer with only node: modules and node --test; the Claude Code hooks-module API (early access) tested with claude plugin test; highlight.js 11.11.1, vendored as published.
Spec
docs/superpowers/specs/2026-11-20-superpowers-reader-design.html

Global Constraints

  • Zero npm dependencies and no build step in the plugin. reader/server.mjs imports only node: modules. No package.json, no node_modules, nothing to install.
  • Never edit anything under superspec/, and never touch its uncommitted files in this worktree. The plugin only symlinks superspec/static/spec.css.
  • Fail open. A missing Node, a dead server, a missing pane or any thrown error never changes a Write or Edit call or its result, and the session carries on.
  • The server listens on 127.0.0.1, prefers port 4520, falls back to an OS-chosen port, and names the host localhost in links.
  • Served documents and media: only paths with a segment named exactly docs; media extensions are exactly png jpg jpeg gif webp mp4 webm.
  • Every server answer carries X-Content-Type-Options: nosniff and Cache-Control: no-store.
  • The page CSP is exactly: default-src 'none'; style-src 'self'; script-src 'self'; img-src 'self'; media-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'none'.
  • No Claude or AI attribution anywhere: no Co-Authored-By trailers, no "generated with" lines, in commits, code, comments or docs.
  • Commits use Conventional Commits. A multi-line message goes through git commit -F <file> or several -m flags, never a heredoc.
  • Never compound cd ... && cmd; run commands from the worktree root with paths.
  • Windows paths are out of scope. Paths are POSIX.

Review Focus

  • File names with spaces, #, ?, % or non-ASCII letters: the module encodes each path segment and the server decodes it, so the page and its media load. Tests: t2-s1, t3-s1, t6-s1.
  • Two writes of the first document in quick succession (a subagent and the main loop, or Write then Edit): one server starts, not two. Test: t6-s1 (concurrent writes).
  • A second session already holds port 4520: the module uses whatever port the server prints, never 4520 by assumption. Tests: t3-s1 (CLI), t6-s1 (port 4521).
  • A document that is momentarily empty or not yet an article (a rewrite in progress): the fragment answers 404, the page shows its gone line and keeps the last content, and the next good poll removes the line. Tests: t3-s1 (empty file), t5-s5 (live check).
  • /reader with no path in a large repository: the walk skips dot directories and node_modules, so a newer file there is never picked and the command answers promptly. Test: t6-s1 (newest skips node_modules).

    export const MEDIA_EXT = ['png', 'jpg', 'jpeg', 'gif', 'webp', 'mp4', 'webm']
/** 'doc' for name.html, 'media' for name.<MEDIA_EXT>, under a segment named exactly docs; else undefined. */
export function docKind(path /* string */) /* : 'doc' | 'media' | undefined */
/** True when the first element, after white space, a BOM and HTML comments, is <article>. */
export function startsWithArticle(text /* string */) /* : boolean */
  • docKind takes an already decoded, absolute path. It is pure: no imports, no file system.
  • It answers undefined for a relative path, a NUL byte, an empty segment, a . or .. segment, a docs segment that is the last one, or a file name with nothing before its extension.
  • Extensions compare case-insensitively (builder's call: A.HTML written on a case-insensitive disk is the same file).

/** Listens on 127.0.0.1:preferred; on EADDRINUSE listens on port 0. Resolves the bound port. */
export function listenPreferred(server, preferred = 4520) /* : Promise<number> */
Routes, as the server answers them
RequestAnswer
/s<abs path> with docKind doc200 page, text/html; charset=utf-8.
same with ?fragment=1200 file bytes with a strong ETag, or 304 on a matching If-None-Match.
/s<abs path> with docKind media200 or 206 with Accept-Ranges: bytes; 416 for an unsatisfiable range.
/_/spec.css, /_/page.csstext/css; charset=utf-8.
/_/page.js, /_/highlight.min.jstext/javascript; charset=utf-8.
Wrong Host name403.
Method other than GET and HEAD405 with Allow: GET, HEAD.
Anything else404.
  • Order of checks: method (405), then Host (403), then route.
  • The Host name is the header's value without its port; only 127.0.0.1 and localhost pass.
  • A document or media path is decoded with decodeURIComponent (a malformed escape is 404), normalised with path.posix.normalize, then checked with docKind; then fs.realpath is checked with docKind to the same kind; then stat.isFile(); then, for a document, startsWithArticle of its text. Any failure is 404.
  • Media is served for any path docKind calls media, not only under assets/ (the spec's "Which files are served" section is the rule; its route table's assets row is the usual case).
  • The ETag is the quoted hex SHA-1 of the bytes (builder's call: exact under same-second rewrites, where size and mtime are not).
  • The page is the spec's template exactly, with the fragment unchanged inside <main>. The title is the text of the first h1 with tags removed and white space collapsed, else the file name with &, <, > escaped.
  • Every answer, errors included, carries nosniff, no-store and the CSP (builder's call: the CSP on every answer costs nothing and covers a fragment opened directly).
  • HEAD answers the same status and headers as GET with no body.
  • Static files resolve against the directory of server.mjs (new URL('.', import.meta.url)); /_/highlight.min.js is vendor/highlight.min.js.
  • Lifetime: it exits on SIGTERM, SIGINT and SIGHUP, and when process.ppid differs from its value at start, checked every second on an unref'd timer. It does not read standard input (see Open questions).
  • It runs its command line only when it is the entry script, so the tests can import it.

function get(path, { method = 'GET', headers = {} } = {}) {
  return new Promise((resolve, reject) => {
    const req = http.request({ host: '127.0.0.1', port, path, method, headers }, res => {
      const chunks = []
      res.on('data', c => chunks.push(c))
      res.on('end', () => resolve({ status: res.statusCode, headers: res.headers, body: Buffer.concat(chunks) }))
    })
    req.on('error', reject)
    req.end()
  })
}
